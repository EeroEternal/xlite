# 压测调参评估手册（tune.sh：为你的负载选 `TOKIO_WORKER_THREADS`）

本手册给出**可复跑的调参评估流程**：用阶梯实验找线程数拐点、用交错复测确认收益、用每核效率做预算裁决。
工具为 [`scripts/loadtest/tune.sh`](../../scripts/loadtest/tune.sh)，实测参考数据见
[`../dev/loadtest-df-data-appendix-2026-10.md`](../dev/loadtest-df-data-appendix-2026-10.md)。

## 1. 先看吐字率——它决定答案

xlite 的 worker 数收益**绑在 chunk 处理率**上（每个内容块都要过泵/中继/写路径），与"流时长"关系不大：

```
吐字率 = 每流内容块数 ÷ 流时长（秒）
流时长 ≈ 内容块数 × 块间隔(ms) / 1000 + 首字延迟
```

D/F 战役实测（40k VU、同一台 128 核机）：

| 流形 | 吐字率 | 8→32 线程效果 | 结论 | 出处 |
| --- | --- | --- | --- | --- |
| 500 块 × 250ms | 4 块/秒/流 | **+0% 吞吐，CPU +62%** | 取 **8** | §8.7 |
| 3,000 块 × 20ms | 50 块/秒/流 | 8→24 **+125% 吞吐**（24 与 32 同速），24 比 32 **省 28% CPU** | 取 **24**（§8.10 寻优；32 亦可但费核） | §8.9/8.10 |
| 6,000 块 × 10ms（D 形） | 100 块/秒/流 | **未测** | 跑本手册流程 | — |

中间地带、其他硬件、其他压力档**都要实测**——不许从上表外推（§8.9 限定）。

## 2. 三步法

### 步骤 1：线程阶梯（找拐点）

固定流形与 VU，**只变 `TOKIO_WORKER_THREADS`**（单因子），每档一轮：

```bash
tune.sh --chunks 3000 --interval-ms 20 --vus 40000 --workers "4 8 16 32 64" --skip-validation
```

看**窗口速率**随线程数的曲线，取**拐点档**（参考 F 形曲线 965→1503→2006→**2171**→2094，拐在 32；64 回落说明"线程越多越快"不成立）。

### 步骤 2：交错复测（确认收益）

赢家 vs 当前值（baseline）交替各 ≥3 轮：

```bash
tune.sh --chunks 3000 --interval-ms 20 --vus 40000 --workers "4 8 16 32 64" --baseline 8 --repeats 3
```

判据（沿用 §8 判据纪律）：
- **收益 > 2× 轮间波动**才算数（我们的台架噪声 ≈ ±0.5%）；收益与波动同量级 → 加轮次
- 三速率分开看：**窗口完成速率**（主指标，含失败迭代）、整轮汇总、失败率——**不得把窗口速率叫"成功流吞吐"**（§2.2）
- 窗口边界 `(t,计数)→(t,计数)` 落盘（report.md 最右列），保证可复算

### 步骤 3：按核预算裁决

报告给出**每核效率** = 窗口速率 × 60 ÷ 网关核数：

| 场景 | 选择 |
| --- | --- |
| 核宽裕、要吞吐/低时延（在线服务、SLA） | 取拐点档（F 形：**24**——与 32 同速且省 28% CPU） |
| 核紧张/按核计费/多实例共机 | 比每核效率与合并部署：8 线程 2,058 次/核·分钟 > 32 线程 1,655；3 实例 × 8 线程 ≈ 793/s > 单实例 32 线程 621/s |
| 不确定 | 先取 8（下界安全），量到拐点再升；F 形寻优实测 24 为甜点（每核效率 2,195 最高） |

**注意代价口径**：F 形 32 线程 = 网关 CPU 7.7→22.5 核（~2.9×），是**有代价的优化**，不是无成本升级。

## 3. tune.sh 参考

```text
tune.sh --chunks N --interval-ms N --vus N [--workers "4 8 16 32 64"]
        [--baseline 8] [--steady 640s] [--warmup 30s] [--repeats 3]
        [--ttft 500] [--skip-validation] [--dry-run] [--out DIR]
```

- **必填**：`--chunks`（每流块数）、`--interval-ms`（块间隔）、`--vus`（压力档）
- `--dry-run` 只打印计划并做参数自检，**不动任何东西**——先跑它
- 输出 `$OUT/report.md`：阶梯表 + 验证表（窗口速率/TTFT/dur/失败/网关核/窗口边界）+ `fingerprints.txt` + 各轮 `k6.log`/`res.tsv`
- **农场配置跑完自动恢复**（含失败中断，trap 兜底）；网关每轮全新容器，轮间 60s 冷却

台架默认（env 可改）：24 路 mock `127.0.0.1:8081-8104`、`TUNE_BIN`（网关二进制）、`TUNE_IMG`（网关基座镜像）、`TUNE_K6`/`TUNE_K6DIR`（k6 镜像与挂载脚本目录）、`TUNE_DB`（已导入 catalog 的 sqlite）。喂法沿用原始采样配置（`KEEP_BODY=true`、`KEEP_SAMPLE=0.1`、`CHUNK_MAX=64`、`STREAM_TIMEOUT=600000`、`GRACEFUL_STOP=900s`）——改喂法会破坏与历史数据的可比性，如需改动请在报告中注明。

## 4. 其他旋钮的实测结论（省得白测）

| 旋钮 | 结论 | 出处 |
| --- | --- | --- |
| `TOKIO_WORKER_THREADS` | **主杠杆**，随吐字率变号 | §8.7/8.9 |
| `XLITE_UPSTREAM_STREAM_CAP` / `MAX_CONNS_PER_HOST` | 等容重分配仅 +3.4% 速率、TTFT 反损 5.8%——非杠杆 | §6.1 |
| 连接额度（每地址上界） | 16k~40k VU 下从不饱和，别调 | §6.1/7.1 |

## 4.5 网卡预算（跨机/生产必算）

字节率 ≈ **每秒内容块数 × ~194 字节**（实测线开销）。1GbE 实测线速 ~112MB/s ≈ **57.5 万块/秒**：

| 流形 | 块/秒/流 | 1GbE 可承载 VU | 40k VU 需要 |
| --- | --- | --- | --- |
| F（3,000块×20ms） | 50 | **≈11.5k** | ~400MB/s → **≥5GbE** |
| D（6,000块×10ms） | 100 | **≈5.7k** | ~800MB/s → **10GbE** |
| 慢吐字（500块×250ms） | 4 | ≈144k | ~8MB/s → 随意 |

实测（§8.11）：1GbE 上 F@10k 之内 0% 失败、达成率 95%+；超预算即大面积失败（40k 短流 80%）。**跨机/生产部署先算这笔账**，再谈线程数。

## 5. 边界

- 参考数字来自**单一台架**（128 核 Xeon 6530、全链路回环）；他硬件需重测
- 单轮差异 < 2× 噪声不得下结论；探针口径（1 轮）只能筛方向
- 窗口完成速率含失败迭代；成功流吞吐需同窗成功计数（k6 侧增强，未做）
- 本流程只调**运行参数**；改代码（数据泵等）属 P4 范畴，须先采样后动刀（§7）
