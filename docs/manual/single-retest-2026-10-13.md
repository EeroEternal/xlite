## 测试计划

1. 构建版本固定到完整 commit SHA，运行 Rust mock 契约测试；记录二进制 SHA256、编译器与 k6 版本。
2. 冒烟：直连 mock 与经过 xlite 分别验证状态码、SSE 结束标记、帧数、字节数和首字节基线。
3. 先跑 mock 直连容量预检，监测 CPU、内存、网络与连接；若农场或链路已饱和，则标注限制，不将该档归因于网关。
4. 正式档位：`1000 2000 5000 10000 15000 18000`，每档 30s 爬坡 + 300s 稳态，600s graceful stop；总 VU 始终小于 20,000。
5. 诊断主线计划使用 100% 请求响应体采样，每请求最多 128 个 chunk 间隔样本，防止无界 Trend 样本耗尽 k6 内存。每档记录实际样本数；时间戳间隔是 mock 生成间隔，不是客户端逐块到达间隔。
6. 1k / 2k / 5k / 10k 同时保留与历史日志约 50% 响应体采样相匹配的对照线。两条采样线分开报告，不拼接吞吐曲线；原始脚本未知，仍不能声称严格同环境对照。
7. 若单个 k6 成为瓶颈，采用多 k6 进程分担总 VU，不增加网关实例；记录分片数、各片结果与资源。不可把各片 p99 求平均冒充整体 p99。
8. 优先复跑关键档位验证差异；因资源不足、失败或未完成的档位全部保留，不只挑最优结果。

- 同时报告整轮 QPS、TTFT p50/p90/p95/p99、HTTP/迭代时长、失败计数、在途估计、CPU、容器内存和 mock 配置；网络吞吐能取得时注明采集方法，否则保持未知。
- 整轮 QPS 与历史整轮 QPS 比较；若新增稳态 QPS，单独列出，不与历史整轮 QPS混算。
- 单进程闭式在途估计使用 `VU × HTTP 平均时长 / 迭代平均时长`，并与稳态连接/请求观测交叉核对；多进程分别估计后相加，不使用分位数代替平均值。
- `gateway_overhead_ms` 只是 `receiving − mock 时间戳跨度`，可为负，不能单独作为网关快慢的裁定。

- 出现明显 OOM 风险、其他服务受影响、持续失败或已确认 mock/链路饱和时停止升档，先定位原因。保留失败工件与退出码。
