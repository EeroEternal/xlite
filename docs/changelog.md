## [Unreleased]

- **Per-host dial gate for h1 (`TransportConfig.max_parallel_dials`, default 4 — xlite#96 follow-up)**: a cold h1 pool fired every waiting request's SYN in one tight batch; against a small accept queue the kernel silently drops the overflow and every dropped SYN costs ~1 s in retransmit (measured: a `listen(5)` mock turned a 16-way burst into 1–2 s of first-wave latency and a 4.5× A/B gap, while the same workload at healthy backlogs was parity). `HostPool::acquire_dial()` now bounds concurrent dials **per authority** — different hosts never throttle each other, the slot covers the TCP+TLS connect only, and the h2 pool already serialized dials so this backend needed nothing. The standalone gateway's h1 path uses the same gate (first dial and the stale-keep-alive redial in `post_h1`); on a healthy server the only effect is a `ceil(N / 4) × connect-time` cold-start ramp, sub-millisecond on a LAN. `0` clamps to `1`; the knob is caller-owned like every other budget, and the gate is pinned by `dial_gate_bounds_concurrency_per_host` (limit holds, per-host independence, release lets the fifth dial proceed).

- **`H1Transport` (issue #96, feature `h1`)**: the `Transport` contract over the extracted HTTP/1.1 pool — one request per `execute()` (the stale-keep-alive race surfaces typed as `StaleConnection` for `execute_redial_once` to redial exactly once; `HeaderTimeout` is never replayed), caller headers verbatim with only `content-length`/`host` synthesized and reported in `headers_rewritten` (`transfer-encoding` is rejected as `InvalidRequest` before any I/O, never silently dropped), truncation mapped to `BodyIncomplete`, drop-closes-the-socket cancellation, and exact per-authority telemetry: `connections` via an `H1Stream` drop-gauge (every death path counts), `dials`/`failed_dials`/`reused`/`evicted`/`evicted_stale`, and `reaped_idle: Some(..)` — h1 counts reclamation from day one (better than the agreed Phase-1 `None`). Parsed response headers are now carried verbatim (duplicates preserved) for both the gateway and the transport; `ParsedResponseHead` gained `headers` and `http_version`.

- **H1 pool extracted into `xlite-transport` (issue #96 item 0)**: `H1Stream` / `HostPool` / `H1Pool` / `dial_h1` / `render_h1_head` / `send_and_read_h1_head` / response-head parsing / `H1Body` moved out of `src/upstream.rs` into `crates/xlite-transport::h1` (feature `h1`; the TLS handshake gated by `tls-rustls`), so the standalone gateway and the transport crate run **one** copy. The gateway keeps its policy — `gateway_h1_headers()` still owns `content-type` / `connection: keep-alive` / auth / extra headers while the shared `render_h1_head()` only renders the `HeaderMap` it is given (the hardcoded `POST` + `application/json` builder is gone); deadlines, the stale-keep-alive redial and endpoint resolution stay in `src/upstream.rs` above the transport. Dial failures are tagged by `io::ErrorKind` (`AddrNotAvailable` = DNS, `InvalidData` = TLS) for typed transport errors, and `configure_tcp_socket` (NODELAY + the 30s keepalive probe budget from #93) moved alongside so both backends share it. Extraction is behaviour-neutral for the binary: the root suite (84 tests, including the h1 keep-alive/redial and ALPN-fallback tests) passes unchanged; root sheds the `httparse`, `socket2` and `itoa` dependencies.

- **New crate `crates/xlite-transport` (Phase-1, issue #96)**: an in-process server-side transport client — `Transport::execute` is exactly one upstream attempt, `execute_redial_once` is the visible, countable exception for the stale-before-first-byte class only (`HeaderTimeout` / `Stall` / `Tls` / `BodyIncomplete` never redial), `Attempt::validate()` rejects bad URIs and contradictory `content-length` before any socket exists, `TransportError` is a typed non-exhaustive enum with `source()`, `BodyStream` cancels upstream on drop and only runs an inter-chunk watchdog when the caller configured `stall_timeout` (one observer per attempt), and `HostStats` reports `None` where a backend cannot measure (never 0-as-unknown) with `evicted_stale <= evicted` invariant. The **h2 backend** (`H2Transport`, feature `h2`) pools per `scheme://authority` via `xlite-h2-pool`, passes caller headers verbatim (mechanical rewrites — RFC 9113 strips, synthesized `content-length`/`host` — are reported per attempt in `headers_rewritten`), classifies truncated bodies as `BodyIncomplete` and typed resets as `Reset { code }`, and projects exact pool telemetry (`reused`, `failed_dials`, `evicted`, `evicted_stale`, wait percentiles) into `TransportStats`. Features `h1` / `h2` / `tls-rustls`; `cargo tree --no-default-features` is gated (`scripts/check_transport_deps.sh`) to keep the crate free of `sqlx` / `axum` / `redis` / `serde_yaml`.
- **Typed stream errors and per-acquire telemetry in `xlite-h2-pool`**: the body channel now delivers `PumpError` (`Reset { code }` / `Closed` / `Io` / `NotPinned`) instead of `Result<Bytes, String>`, so callers classify failures without string matching; `Lease::wait()` reports the per-acquire parked time (`Some(0)` = acquired immediately) and `Lease::dial_time()` reports how long the dial took (`None` when a pooled connection was reused — a different fact from a zero-time dial); `PoolStats` and `GET /api/pool` gain `reused` and `failed_dials`.

- **`evicted` pool counter (`PoolStats`, `GET /api/pool`, `crates/xlite-h2-pool`)**: connections the pool stopped trusting (`Lease::evict` on a header timeout or transport error, or a connection driver that ended while a stream was still in flight) are now counted separately from `reclaimed` (idle housekeeping) and surfaced in `/api/pool` — a rising `evicted` says the pool keeps finding sockets it can no longer trust (the degrading-path signal behind #90), while `reclaimed` still means "the reaper tidied up" and a routine idle close counts as neither; the unknown-host snapshot and the existing `PoolStats` comparison test were updated to match.

## [0.8.0] - 2026-10-24

- **Dead upstream detected in 30s instead of 120s (`src/upstream.rs`)**: the upstream socket keepalive never set `TCP_KEEPCNT`, so the kernel used its default of 9 probes — with `time=30s, interval=10s` a blackholed peer took `120s` to fail, exactly as long as the header timeout, which meant the kernel's own signal always arrived too late to be useful and every later request inherited the stall. The budget is now `15s + 3 × 5s = 30s` (`with_retries(3)`), so a dead path surfaces as a transport error and fails over while the header-timeout watchdog is still only a quarter spent. No new dependency, no new env var.

- **Header timeout now evicts the connection (`src/upstream.rs`)**: an attempt that expires waiting for upstream headers removes its HTTP/2 connection from the pool, so the next request dials a fresh one instead of multiplexing onto a socket that just proved it cannot answer — a blackholed connection used to stay pooled (`connections=1, dials=1`) and cost every later request a full timeout window; the next acquire now redials (verified: 502 at 120s, `connections=0`, next request 200 on `dials=2`), and in-flight streams on the evicted connection keep their lease and finish. Reported via #90.

- **Opt-in TLS key log (`XLITE_SSLKEYLOG`; `src/keylog.rs`, `src/upstream.rs`, `docs/manual/xlite.md`)**: setting `XLITE_SSLKEYLOG` to a path (or `1` to reuse `SSLKEYLOGFILE`) installs a rustls key log on both upstream TLS connectors so `tshark`/Wireshark decrypts the capture and HTTP/2 frames become visible — it is the only way to verify on the wire that a client disconnect sends `RST_STREAM(CANCEL)` rather than tearing the connection down (verified on a live DeepSeek stream: `RST_STREAM` on stream 3, error `CANCEL`, 3.0s after the request started). Unset means the client config keeps rustls' no-op key log, so nothing is derived or written; when enabled it logs an `xlite.security` warning because session secrets land on disk in plaintext, so it is debug/testing only.
- **Timeouts are on by default (`XLITE_UPSTREAM_HEADER_TIMEOUT_SECS=120`, `XLITE_UPSTREAM_STALL_TIMEOUT_SECS=300`; `src/config.rs`, docs, `deploy/env.example`)**: both watchdogs now have non-zero defaults (explicit `0` still disables them, unparsable values keep the default instead of silently disabling), so a wedged upstream connection self-heals within minutes instead of holding its pool slot forever — the failure mode behind issue #90. `300s` is also documented as the longest a stuck body can occupy a slot; `XLITE_SLOW_WARN_MS` is shown as a commented example.

- **Hang diagnostics (`xlite.timing`, `XLITE_SLOW_WARN_MS`; `src/upstream.rs`, `src/proxy.rs`, `docs/manual/xlite.md`)**: an opt-in tracing target prints one line per upstream phase (`acquired`, `headers`, `attempt-done`, `body-first-chunk`, `body-end`) with elapsed milliseconds and channel id, so a stuck request reveals the last phase it reached instead of leaving only `/api/pool` counters to guess from; `XLITE_SLOW_WARN_MS` (default off) emits a single `xlite.slow` warning when an attempt waits too long. This is the diagnostic hook for issue #90.

- **Per-provider timeout overrides (`providers.header_timeout_secs` / `stall_timeout_secs`, migration `004`, `src/store.rs`, `src/proxy.rs`)**: a provider can bound its own request→headers wait and mid-stream stall window instead of inheriting the global values — a flaky upstream is now isolated without tightening timeouts for everyone else; the header-timeout path fails over like a transport error (attempt recorded, channel cooled down), and omitted fields keep the previous behaviour.

- **Per-channel concurrency cap (`channels.max_concurrency`, migration `003`, `src/store.rs`, `src/proxy.rs`, `src/admin.rs`)**: a channel can declare an in-flight limit that is enforced at admission instead of by queueing — overflow fails over and then sheds with `503` + `Retry-After: 1` (`overloaded_error`), the slot is held for the response body's lifetime (so a long stream keeps it, a client disconnect frees it), the channel is never cooled down for being busy, uncapped channels touch no atomic, and `GET /api/channels` reports `in_flight` next to `max_concurrency`.

- **Request priority, `Retry-After`-aware cooldowns (`src/proxy.rs`, `src/upstream.rs`, `crates/xlite-h2-pool`)**: `x-xlite-priority: bulk` makes a request shed (`503` + `Retry-After: 1`, `overloaded_error`) instead of queueing once its channel's pool would park, so latency-sensitive traffic keeps the queue; a shed attempt is reported with `status: 503`, `cooled_down: false` and never cools the channel down. Failover cooldowns now honour the provider's `Retry-After` hint (clamped to 1–300s, never below the status default) on both the HTTP/2 and HTTP/1.1 response paths.

- **Per-attempt event stream, per-channel pool metrics, durable operator cooldowns (`src/proxy.rs`, `src/store.rs`, `src/admin.rs`, `docs/manual/xlite.md`, `deploy/env.example`)**: `XLITE_ATTEMPT_WEBHOOK_URL` now posts one event per upstream attempt as it finishes (joined to the batch report by the new `request_id`); `GET /api/channels` reports each channel's live pool (`connections`, `in_flight`, `waiting`, `effective_ceiling`, `wait_ms_p50`/`p99`) alongside its cooldown; operator cooldowns are stored outside the routing snapshot so they survive reloads (including credential changes), apply to catalog channels that are not routed yet (`pending_reload`), and clearing one also clears the carried-over cooldown.

- **Per-attempt telemetry & caller-side cooldown control (`src/proxy.rs`, `src/store.rs`, `src/admin.rs`, `docs/manual/xlite.md`)**: the usage webhook payload now carries an ordered `attempts[]` trail (`channel_id`, `provider_id`, `upstream_model`, `status`, `error`, `latency_ms`, `cooled_down`) so a control plane can attribute failures, retries and cooldowns per channel instead of only seeing the final result; `GET /api/channels` reports each channel's live `cooling_down` / `cooldown_remaining_ms`, and `POST /api/channels/{id}/cooldown` sets or clears that cooldown (`0` clears, unknown ids return `404`).

## [0.6.4] - 2026-10-17

- **Lock-free multi-host pool lookup & zero-copy HTTP/1.1 vectored writes (`crates/xlite-h2-pool/src/pool.rs`, `src/upstream.rs`)**: Replaced the single-entry `last_host` cache and `Mutex<HashMap<...>>` in `xlite-h2-pool`, `H1Pool`, and `h1_tls_hosts` with `ArcSwap`-backed maps/sets so concurrent routing across multiple upstream authorities executes with zero mutex contention and zero per-request `String` allocations; switched cleartext HTTP/1.1 request forwarding to `write_vectored` (`writev`) to send request headers and bodies in a single syscall without intermediate buffer copying.
- **Transparent 1x redial on stale reused HTTP/2 connections (`crates/xlite-h2-pool/src/lease.rs`, `src/upstream.rs`)**: Added `Lease::is_reused()` and `Lease::evict()` so that when a warm pooled HTTP/2 connection (`h2c` or `ALPN: h2`) is silently dropped by an upstream or intermediate NAT/firewall before response headers arrive, `xlite` immediately evicts the dead connection and transparently redials once before triggering channel failover or transient cooldown.
- **Channel cooldown preservation across catalog reloads (`src/store.rs`)**: `Store::reload()` now carries over active `cooldown_until_ms` deadlines for channels whose `id`, `base_url`, `api_key`, and `upstream_model` are unchanged, while immediately clearing cooldowns when a channel's target or credentials are updated by an operator.

## [0.6.3] - 2026-10-17

- **Native TLS HTTP/2 (`ALPN: h2`) upstream pooling with zero-waste HTTP/1.1 fallback (`src/upstream.rs`)**: Wired `https://` endpoints (such as DeepSeek `api.deepseek.com` and Xiaomi MiMo `api.xiaomimimo.com` / `token-plan-*.xiaomimimo.com`) into `xlite-h2-pool` via TLS ALPN `["h2", "http/1.1"]` negotiation (including RFC 9113 `content-length` headers for HTTP/2-to-HTTP/1.1 edge proxy compatibility), enabling peer `SETTINGS_MAX_CONCURRENT_STREAMS`-aware stream multiplexing, `RST_STREAM(CANCEL)` propagation, and `/api/pool` visibility over TLS; if an `https://` peer negotiates `http/1.1`, the already-handshaked TLS socket is parked directly into `H1Pool` and reused with zero extra handshake.
- **Lock-free per-channel failure cooldown (`src/store.rs`, `src/proxy.rs`)**: Added an `AtomicU64` monotonic cooldown deadline on `Channel` (`30s` on `401–404` quota/auth/route errors, `5s` on `408`/`429`/`5xx` and transport/header timeouts) so `order_channels` immediately places healthy backup channels ahead of cooling-down channels without paying repeated upstream RTTs, while keeping cooling-down channels at the tail so traffic is never blackholed if all channels are simultaneously in cooldown.
- **Expanded pre-first-byte failover on `HTTP 401 / 402 / 403 / 404 / 408` (`src/upstream.rs`)**: Extended `should_failover` to treat upstream `402 Payment Required` (account balance or credit exhaustion), `401 Unauthorized` / `403 Forbidden` (single-key revocation in a multi-key pool), `404 Not Found` (missing model on a subset of providers), and `408 Request Timeout` as retryable channel failures before the first response byte is sent.
- **Admin UI Xiaomi MiMo preset & Token Plan auto-resolution (`admin/src/lib/inner-providers.ts`, `admin/src/pages/models.tsx`)**: Updated the built-in Xiaomi provider preset with the official OpenAI-compatible pay-as-you-go endpoint (`https://api.xiaomimimo.com/v1`), Token Plan subscription endpoint (`https://token-plan-cn.xiaomimimo.com/v1`, automatically selected when `tp-` / `ttp-` API keys are used), and current 1M-context models (`mimo-v2.6-pro`, `mimo-v2.6-flash`, `mimo-v2.6-pro-ultraspeed`).

## [0.6.2] - 2026-10-17

## [0.6.1] - 2026-10-16

- **SSE anti-buffering headers, `: keep-alive` heartbeats (`XLITE_SSE_KEEPALIVE_SECS`), and upstream TCP/H2 keepalive (`src/proxy.rs`, `src/upstream.rs`)**: Automatically emit `Cache-Control: no-cache` and `X-Accel-Buffering: no` on `text/event-stream` responses, send `: keep-alive\n\n` SSE comment heartbeats every `XLITE_SSE_KEEPALIVE_SECS` (default `15s`, `0` to disable) during silent reasoning pauses without resetting `StallGuard`'s upstream stall deadline, and enable `tcp_keepalive(30s)` plus HTTP/2 adaptive flow-control windows and keep-alive pings on the upstream `reqwest` client.
- **Deploy & `xlite-h2-pool` cleanup**: Removed legacy Node.js 24-mock harness files (`scripts/stream_mock_server.mjs`, `scripts/start_mocks.sh`, `deploy/Dockerfile.mock`, `examples/mock-24*.yaml`, `docs/manual/mock-24-docker.md`) in favor of the standalone `mock-llm` repository, simplified `deploy/docker-compose.yml` to a clean `xlite + Redis` deployment stack, and removed the unused `diag.rs` / `examples/h2probe.rs` scaffolding from `crates/xlite-h2-pool`.
