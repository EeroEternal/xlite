## 1. 核心结论摘要

在严格同拓扑、同入口（双节点 `:8005`）、同 24 口上游 Mock 的实测比对中：

1. **首字延迟（TTFT）：XG 全面领先 100ms ~ 153ms（快 15% ~ 22%）**
   - 在正常健康负载（1000 ~ 4000 VU）下，无论短流、交互流还是超长流，XG 的首字延迟均显著优于 New API：
     - **B 组（常规流 out=500）**：XG TTFT p50 稳定在 **555ms ~ 599ms**，New API 为 **708ms ~ 711ms**，**XG 领先 112ms ~ 153ms（快 21%）**。
     - **D 组（长流 out=6000）**：XG TTFT p50 稳定在 **555ms ~ 609ms**，New API 为 **708ms ~ 714ms**，**XG 领先 104ms ~ 153ms**。
     - **E 组（交互流 out=250）**：XG TTFT p50 稳定在 **604ms ~ 608ms**，New API 为 **708ms**，**XG 领先 100ms ~ 103ms**。
2. **尾部延迟稳定性（p99）：XG 在高并发下排队控制力极强**
   - 在 D 组 5000 VU 临界点：
     - **XG TTFT p99 稳定在 1,456 ms（1.45 秒）**；
     - **New API TTFT p99 瞬间崩溃至 20,093 ms（20 秒！）**，尾部延迟恶化近 14 倍。
3. **0926 轮 5000 VU 停测归因澄清**：
   - 0926 轮在 5000 VU 终止，系当时驱动脚本启用了 `link_budget.py` 农场预算闸门（24 口 Mock batch=1 算力上限测算为 4968 流），为了防止压垮下游 Mock 依规主动停止，**非网关故障**。后续已在提交 `5f96116` 中彻底移除该限制，放开至 60000 VU 对齐客户逻辑。
4. **New API“数万并发 0 失败”的指标解密**：
   - New API 历史测试未配置农场预算闸门，在 5000 VU 之后依赖 600s 超时死等，TTFT p99 飙升至 20~100 秒，QPS 彻底封死在 ~850；实际闭式在途流仅为 3000~4000，名义 VU 严重脱水。

## 3. 关键现象与技术机制深入归因

### 3.1 D 组 6000 VU 的 `k6 rc=137` 真实原因
- **口径差异暴露**：
  - 0924 的 `v88-dual` 日志头部明确写着：`采样: A/E=100% B=50% C/F=10% D=5%`。其在测试 6000 chunk 长流时，**仅对 5% 的响应进行 body 解析**，95% 的数据只读不存，因而避开了 k6 内存暴涨。
  - 0926 轮设定为 `KEEP_BODY=true KEEP_SAMPLE=1`（100% 全量解析）。在 6000 个在途连接下，每个连接全量缓冲巨型流，导致 **45GB 内存被 k6 自身打满**，被 Linux OOM killer 终止（退出码 137）。
- **结论**：D 组 6000 VU 的中断纯属**压测端客户端内存瓶颈**，降采样重试后 XG 在 6000~9000 VU 下 TTFT p50 依然维持在 **639ms ~ 719ms**（New API 此时已恶化到 902ms ~ 1465ms，p99 达到 46~74 秒）。

### 3.2 农场预算闸门演进与当前状态
- 0926 轮在 17:43 启动时，驱动脚本内置了根据物理核心测算的 `4968 VU` 农场容量保护。
- 在观察到该拦截截断了对标阶梯后，已于 **2026-09-26 18:33 提交 `5f96116`**：
  - 移除了 `run_full_88_xg.sh` 中的 `v88_farm_vu_cap` 拦截判断；
  - 默认 `MAX_VUS` 全额放开至 `60000`；
  - 完全对齐客户压测“只按连续两档失败率 > 1% 停测”的行为。
- 后续压测将直接冲刺更高档位。

## 4. 总结与客户对标汇报口径

1. **同载荷质量领先**：在双方均稳态运行的 1000 ~ 4000 VU 区间，XG 展现了**首字快 100~150ms（-21%）**的确定性优势，同时在 5000 VU 极限载荷下保持了 **1.45s vs 20s 的极端排队控制力**。
2. **容量自证**：结合 `bench/0924/xg-dual` 的满负荷测试，在脱离客户端解析瓶颈后，XG 能够稳定承载 **31,000 ~ 44,000 VU**（QPS 1682 / 3495，fail < 1%），证明高并发连接与流转发能力远超 New API。
